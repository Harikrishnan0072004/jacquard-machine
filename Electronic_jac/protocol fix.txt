# USB→SD Copy Protocol Fix — nc/totaldata Mismatch Bug

## Problem Summary

Bug: USB folder/file copy produces oversized or corrupted destination files
when the source file was created on a system with a different `nc`
(cards-per-ribbon) configuration than the system performing the copy.

Root cause: `height` (pick count) and `totaldata` (bytes-per-pick) were
being GUESSED from file size and the copying system's global `nc` value,
instead of being read from the file's own BMP header. This caused wrong
pick boundaries, wrong byte counts sent/received, and mismatched
destination file sizes.

Confirmed example: file "8-8A" (14,270 bytes) was created with nc=9
(totaldata=148, height=96 — exact match). System nc=12 guess produced
totaldata=196, height=73 — completely wrong, causing corrupt oversized
output.

## Fix Overview

1. Read `height` from the file's BMP header (offset 0x16) instead of
   guessing from file size.
2. Derive `totaldata` for this specific file from (payload bytes / height)
   instead of using the global system `nc`.
3. Sync the derived `totaldata` to the mainboard via the existing `ABct`
   tag packet (adds one extra field), so both sides agree on the same
   per-file byte count. Uses a new local variable `copyTotalData` so the
   global `totaldata` used by the live weaving loop is never touched.

## PART 1 — RP2040F.ino Changes

### 1.1 — New function (place near `usbFindHeight()`)

```cpp
// Reads height from file header, derives exact totaldata for this file
// from file size (does NOT use global nc)
bool usbDeriveTotalData(File32 &f, unsigned long srcSize,
                         unsigned long &heightOut, unsigned int &totalDataOut)
{
  heightOut = usbFindHeight(f);
  if (heightOut == 0) return false;

  unsigned long payloadBytes = (srcSize > bitmapOffset) ? (srcSize - bitmapOffset) : 0;
  if (payloadBytes % heightOut != 0) {
    Serial1.println("WARNING: payload not exact multiple of height");
    return false;
  }

  totalDataOut = (unsigned int)(payloadBytes / heightOut);
  return true;
}
```

### 1.2 — Replace height calculation in `usbCopyOneFile()`

BEFORE:
```cpp
unsigned long height;
if (srcSize > bitmapOffset) {
  unsigned long payloadBytes = (srcSize > bitmapOffset) ? (srcSize - bitmapOffset) : 0UL;
  height = (payloadBytes + totaldata - 1) / totaldata;
} else {
  height = 0;
}
if (height == 0)
{
  Serial1.println("ERROR: bad/zero height, aborting file");
  usbSrcFile.close();
  return false;
}
```

AFTER:
```cpp
unsigned long height;
unsigned int fileTotalData;
if (!usbDeriveTotalData(usbSrcFile, srcSize, height, fileTotalData))
{
  Serial1.println("ERROR: could not derive height/totaldata from file header");
  usbSrcFile.close();
  return false;
}
Serial1.print("Derived totaldata="); Serial1.print(fileTotalData);
Serial1.print("  height="); Serial1.println(height);
```

### 1.3 — Replace `totaldata` references with `fileTotalData` (same function, below)

BEFORE:

## PART 2 — mainboard.ino Changes

### 2.1 — New global variable (near `totaldata` declaration)

```cpp
unsigned int copyTotalData = 0;   // USB copy only, weaving loop never touches this
```

### 2.2 — Update `'ct'` tag packet handler

BEFORE:
```cpp
if (data3[2] == 99)        //c - Copy pick no
{
  if (data3[3] == 116)        //t - pick no
  {
    int e = inputString.indexOf('*');
    int  f = inputString.indexOf('#');
    String pick = inputString.substring(e + 1, f);
    copypick = pick.toInt();
    Serial.print("Copypickno : ");
    Serial.println(copypick);
    return;
  }
}
```

AFTER:
```cpp
if (data3[2] == 99)        //c - Copy pick no
{
  if (data3[3] == 116)        //t - pick no (+ optional totaldata)
  {
    int e = inputString.indexOf('*');
    int f2 = inputString.lastIndexOf('*');
    int hashIdx = inputString.indexOf('#');

    String pick = inputString.substring(e + 1, (f2 > e) ? f2 : hashIdx);
    copypick = pick.toInt();

    if (f2 > e) {
      String td = inputString.substring(f2 + 1, hashIdx);
      copyTotalData = td.toInt();
      Serial.print("copyTotalData set: ");
      Serial.println(copyTotalData);
    }

    Serial.print("Copypickno : ");
    Serial.println(copypick);
    return;
  }
}
```

### 2.3 — Replace `totaldata` with `copyTotalData` in card-data receive block only

Inside `rundesign1()`, the block handling `data3[3] == 101 || data3[3] == 115`
('e'/'s' — card data). Replace every `totaldata` reference WITHIN THIS BLOCK
ONLY with `copyTotalData`:

```cpp
if ((data3[3] == 101) || (data3[3] == 115))   // 'e' or 's' - card data
{
  nc2 = 0;
  unsigned long cardTimeout = millis();

  while (nc2 < copyTotalData) {              // was: totaldata
    if (Serial2.available() > 0) {
      data1[nc2] = (byte)Serial2.read();
      nc2++;
      cardTimeout = millis();
    }
    if (millis() - cardTimeout > 2000) {
      Serial2.print('D'); Serial2.print('0');
      Serial2.flush();
      return;
    }
  }

  if ((lastcopypick + 1) == copypick)
  {
    bMap4.seek(((copypick - 1) * copyTotalData) + bitmapOffset);   // was: totaldata
    for (int i = 0; i < copyTotalData; i++) {                      // was: totaldata
      bMap4.write(data1[i]);
    }
    bMap4.flush();
    lastcopypick = copypick;
    Serial2.print('D'); Serial2.print('1');
  }
  else
  {
    Serial2.print('D'); Serial2.print('0');
  }
  Serial2.flush();

  if (data3[3] == 115) {
    bMap4.close();
    lastcopypick = 0;
    copypick = 0;
    copyTotalData = 0;   // reset — see 2.4
  }
  return;
}
```

IMPORTANT: Do NOT change `totaldata` anywhere else in the file
(onepulse2(), file1output(), file2output(), down(), jump(), jump1(),
runninginit(), etc.) — those are the live weaving path and must keep
using the global system `totaldata`.

### 2.4 — Reset `copyTotalData` on file close

Already included in 2.3 above (`copyTotalData = 0;` inside the
`data3[3] == 115` branch). This ensures the next copy operation starts
fresh and nothing stale leaks into the weaving loop.
