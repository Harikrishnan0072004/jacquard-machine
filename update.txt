## Important Updates Needed

1. **Fix invalid EEPROM validation**  
   In `mainboard.ino:132`, this condition can never be true:

   ```cpp
   if ((nc > 32) && (nc <= 0))
   ```

   Use:

   ```cpp
   if (nc <= 0 || nc > 32)
   ```

   Also normalize the EEPROM value before using it. An invalid `nc` can produce incorrect buffer sizes and file calculations.

2. **Add bounds checks to folder/file arrays**  
   `filelist[50]` and `folderlist[50]` are written without checking whether the count has reached 50 in mainboard.ino and mainboard.ino. Add limits before assigning array entries.

3. **Prevent RP2040 USB buffer overflow**  
   In `RP2040F.ino:1300`, these buffers are fixed at 600 bytes:

   ```cpp
   uint8_t pickBuf[600];
   uint8_t txBuf[600];
   ```

   However, `fileTotalData` is calculated from the file and may exceed 600. Reject files larger than the buffer or use a controlled streaming buffer.

4. **Fix USB mount failure handling**  
   In `RP2040F.ino:408`, the mount-failure assignment is commented out. Therefore `usbMountFailed` remains false and the error screen in `usbWaitForMount()` is never reached.

5. **Improve file validation**  
   `RP2040F.ino:957` does not verify that reads succeeded. Also validate:
   - BMP header signature
   - height is nonzero
   - calculated `fileTotalData` is nonzero
   - calculated size does not exceed buffer limits

6. **Review folder-copy behavior**  
   `RP2040F.ino:1698` returns failure when the destination folder already exists. This prevents copying missing files into an existing folder, while single-file copying treats an existing folder as valid. The behavior should be made consistent.

7. **Reduce blocking loops and `goto` control flow**  
   Both firmware files contain many `while (true)` loops and `goto` labels. A disconnected USB device, missing serial response, or keypad failure can leave the controller permanently blocked. Replace the highest-risk loops with state machines or timeout-returning functions.

8. **Reduce debug logging in production**  
   The RP2040 transfer path prints every packet, byte, retry, and CRC message at 230400 baud. This can affect timing during serial transfers. Add a compile-time debug flag.

9. **Check protocol consistency**  
   CRC is calculated and transmitted by the RP2040, but the mainboard protocol should be verified to ensure it validates the CRC before writing data. The comment `//must addcrc` remains in `mainboard.ino:102`.

10. **Close or remove legacy code**  
   The RP2040 sketch combines the current USB-copy system with older SD/menu/test functionality. This makes maintenance and testing difficult. Separate active code from deprecated code or move unused code into an archive sketch.
